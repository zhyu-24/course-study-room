# AI Course Archive — 课程资料编译规范 v1.0

## 1. 目的与适用范围

本规范用于把一门工科课程的原始资料编译为稳定、可读、可检索、可追溯的知识档案。它适用于数学、物理、信号、控制、电路、计算机等包含公式、推导和例题的课程。

编译不是摘要，也不是自由创作。目标是在不改变原意的前提下重组知识结构，并为关键内容保留可回到原始资料的定位符。

## 2. 标准产物与职责边界

| 文件 | 唯一职责 | 不应包含 |
|---|---|---|
| `Course_Index.md` | 课程入口与导航 | 定义、长摘要、推导 |
| `Global_Knowledge.md` | 跨课程的知识结构与依赖 | 教材逐章复述、完整例题 |
| `Global_Source_Map.md` | 全局资料的结构与检索地图 | 教学正文 |
| `Lecture_Notes.md` | 单节课的标准学习版本 | 原始 transcript 式流水账 |
| `Lecture_Source_Map.md` | 单节课的证据定位与质量记录 | 第二份课程笔记 |

## 3. 目录与命名规则

```text
<Course_Name>/
├── Course_Index.md
├── Global/
│   ├── Global_Knowledge.md
│   ├── Global_Source_Map.md
│   └── Raw/
└── Lectures/
    └── L01/
        ├── Lecture_Notes.md
        ├── Lecture_Source_Map.md
        └── Raw/
```

- 课程目录和原始文件名可按个人习惯命名，但路径一旦进入 Source Map 后尽量不改。
- Lecture 编号固定为 `L01`、`L02`……；补课或专题课可用 `L03A`，不要事后整体重编号。
- 原始文件只放入 `Raw/`，不得因“清理”而覆盖、裁剪或删除原件。派生文件需使用新文件名。
- 五类标准文档使用固定英文文件名，正文可用中文。

## 4. 最少 metadata

只使用模板中已有字段。必填：`type`、`course`、`status`；单节课另填 `lecture`。`date` 和 `term` 完全可选：来源没有明确给出时直接省略，AI 不得仅为了补齐日期而询问用户。已知时填写 `topic`、`updated`，其他未知信息可省略或按模板要求写 `unknown`，不要猜。

状态只允许：

- `draft`：AI 编译和自检完成。
- `reviewed`：人类完成关键检查。
- `verified`：关键结论已回源核验。

## 5. 证据模型

### 5.1 内容性质

- **FACT**：来源直接支持的定义、公式、结论、题目或课程安排。正文默认按 FACT 写，但必须能在 Source Map 找到证据。
- **EXPLANATION**：教师明确给出的直觉、类比、经验、提醒。应放在教师解释区并保留录音或 transcript 定位。
- **DERIVED**：AI 仅依据已给来源做的重排、归纳或显式中间推导。凡新增了来源未写出的数学步骤、分类或关系，使用 `[Derived: ...]` 简短标明依据。
- **UNCERTAIN**：无法可靠确认、来源冲突、缺失或识别错误。使用 `[?]`；来源冲突使用 `[!]`。

### 5.2 默认来源优先级

1. 教材、课程官方 handout、教师发布的公式表
2. 教师 PPT
3. 板书或手写内容
4. 课堂录音原音
5. transcript
6. AI reconstruction

这不是机械裁决规则。教师在课堂上明确说“上一页有误”“这里修正为……”时，修正后的课堂表述可以覆盖 PPT，但必须同时记录原内容、修正定位和判断理由。

### 5.3 来源 ID 与定位符

- 全局来源使用 `G1`、`G2`……；单节来源使用 `S1`、`S2`……。
- PDF：`S1 PDF p.12`；若印刷页不同，加 `/ printed p.8`。
- PPTX：导出或读取后的 slide 编号写成 `S1 slide 12`。
- 教材：`G1 Ch.3 §3.2, PDF p.88`。
- transcript：优先时间段 `S2 00:12:40–00:14:05`；无时间戳时使用稳定行号 `S2 lines 180–226`。
- 音频：`S4 00:12:38–00:14:08`。
- 图片：`S3 board_02`；局部可进一步写 `upper-left` 等可复现位置。

每个重要定义、关键公式、主要推导、课堂例题和教师强调至少有一个可用定位符。一般解释段落可共享段末锚点，不要求逐句标注。

## 6. 编译流程

### Stage A — Intake

1. 列出所有文件，记录类型、文件名、页数或时长、是否可读。
2. 不把“文件存在”等同于“内容已成功读取”。
3. 对 slides、recording、transcript、board images、textbook/handout 分别记录 `provided-readable`、`provided-partial`、`provided-unreadable`、`not-provided` 或 `not-applicable`。
4. 建立 Source Inventory，只给实际提供的来源分配稳定 ID。
5. `not-provided` 表示本次输入边界，不自动构成失败；编译仍应基于现有来源正常完成，并说明无法覆盖的内容类型。
6. 用户明确表示已提供但未进入处理的文件，或读取失败却未声明，属于覆盖错误。

### Stage B — Source preparation

- 保持原始文件不变。
- PPT/PDF 按页读取；若 PPT 动画导致同页多状态，应在 Source Map 说明。
- transcript 保留时间戳；若无时间戳，保留稳定行号或段落号。
- 图片按拍摄顺序编号；旋转或增强后的副本标为派生文件。
- 录音用于核对语气、术语、数字和 transcript 疑点，不默认重新逐字转写整段。

### Stage C — Alignment

建立最低限度的跨来源对应：

- PPT 页段 ↔ transcript/录音时间段
- 板书图片 ↔ 讲解时间段 ↔ PPT 或例题
- 本节 topic ↔ 教材章节

只记录能帮助核验的关键分段。无需逐分钟、逐页强行对应。

### Stage D — Evidence extraction

分别提取：

- 定义及其条件
- 符号、单位和课程约定
- 关键公式、定理和结论
- 推导的起点、关键变换、终点及省略处
- 例题的题目、方法、结果和教师点评
- 教师解释、纠错、重点与明确考试提示
- 与前后主题、教材的关系
- 疑点、冲突和缺失

先完成证据提取，再写成完整笔记，避免由流畅文字反向“补造”证据。

### Stage E — Knowledge reconstruction

`Lecture_Notes.md` 按“概念 → 原理 → 推导 → 例题 → 教师补充 → 关系”重组，不照抄课堂时间线。

允许：

- 改写句式、合并重复说明、调整顺序。
- 展开来源能够唯一决定的纯代数中间步骤，并标记 `Derived`。
- 由多个明确来源归纳主题关系，并标记 `Derived` 与依据。
- 修正 transcript 中能被更高优先级来源明确确认的拼写或术语，同时在 Source Map 记录重要 ASR 错误。

禁止：

- 为“完整”而新增来源没有给出的定义、假设、公式、定理、例题数据或教师意图。
- 仅凭常识静默修正一个可能的教师口误。
- 把 AI 生成的例子写成课堂例题。
- 把“本领域通常如此”写成“教师强调”或“考试重点”。
- 在符号、上下标、正负号、积分边界或单位不清时猜测。

### Stage F — Source mapping

为 Notes 的关键知识项创建 `Knowledge → Source Mapping`。优先给出最权威且最直接的来源，再列辅助来源。Source Map 写定位和质量，不重复解释知识。

### Stage G — QA and human review

1. AI 依据 `QA_Checklist_v1.0.md` 自检并修正可安全修正的问题。
2. 仍未解决的问题集中放入 Notes §6 和 Source Map §5–6。
3. 人类优先检查：关键公式、教师纠错/考试提示、所有 `[?]`/`[!]`、QA 阻断项。
4. 通过快速检查后将两份文档状态同步改为 `reviewed`。

## 7. 各来源处理规则

### 7.1 PPT / PDF

- PPT 提供正式结构、术语和公式骨架；记录 slide 或 PDF page。
- 不把标题页、目录页的主题名称当作已讲授内容。
- 图片中的公式或图注必须实际读取后再录入。
- 同一公式跨页逐步出现时，以最终完整状态为主，并说明必要的构建步骤。

### 7.2 Transcript

- transcript 是检索入口，不是数学事实的最高证据。
- 对同音词、英文术语、变量名、数字、负号、上下标保持怀疑。
- 可由 PPT/教材/板书明确校正的 ASR 错误，正文写正确内容；会影响含义的错误在 Source Map 留痕。
- 无法确认时保留原片段摘要并标 `[?]`，指向需复听的音频时间段。
- 飞书妙记仅可作为可选转写入口：从妙记导出的 TXT（或 SRT）须保留时间戳；如可选说话人，也一并保留。
- 有录音时，导出稿和原始音频必须同时保存在该讲次 `Raw/`。来源映射中的时间戳应能回到这份本地音频。
- 不把妙记网页、共享链接或 AI 的推测当作可读转写稿；未取得本地导出稿时，按实际情况标记 `not-provided` 或 `provided-unreadable`。

### 7.3 Recording

- 优先用于核对 transcript 的疑点、教师语气、明确修正和重点。
- 记录核验片段前后各留少量上下文，避免断章取义。
- 听不清不等于没有讲；写 `inaudible/uncertain`，不得补词。

### 7.4 Board images

- 先确认顺序、方向和可读性，再识别公式。
- 板书推导应保留关键中间步；被遮挡、截断或模糊的符号标 `[?]`。
- 图像中的坐标轴、方向、单位、边界条件属于公式的一部分，不得省略。
- 若板书与 PPT 不同，检查是否是特例、变形、修正或真正冲突。

### 7.5 Textbook and global handouts

- 只定位与课程实际使用相关的章节，不制作整本教材摘要。
- 记录版本和页码体系；不同版教材不能直接复用页码。
- 教材补充背景只有在本节确实使用、解释或建立必要联系时进入 Lecture Notes。
- 未在课程资料中使用的通用背景知识，不进入 canonical note；可在答疑时临时解释。

## 8. 数学、推导和例题规则

### 8.1 公式

- 使用标准 LaTeX；首次出现的关键符号说明含义、单位和域。
- 保留等号/近似号、向量/矩阵、上下标、复共轭、变换方向、求和与积分边界。
- 每个关键公式同时保留成立条件。条件不明时，公式不得写成无条件事实。
- OCR/ASR 与视觉来源不一致时，优先人工可见公式，并登记差异。

### 8.2 推导

- 至少保留：起始式、关键依据、非显然步骤、最终结论和适用条件。
- 不为缩短篇幅删除决定结论成立的步骤。
- 来源确实跳步时，可以补唯一确定的代数步骤；不得补新的理论假设。
- 无法恢复的中间步骤写入不确定区，不伪造完整证明。

### 8.3 例题

- 课堂出现的主要例题均应进入 Notes 或明确说明为何略过。
- 保留题设、已知条件、目标、方法、关键计算、结果和教师点评。
- 区分：`课堂例题`、`教材例题`、`AI 派生练习`。v1.0 canonical note 默认不加入 AI 派生练习。
- 若教师只讲思路未给最终结果，明确写“来源未给出最终结果”。

## 9. 冲突、口误、缺失与不确定性

- **ASR error**：能被其他来源确定时可修正；影响含义时留痕。
- **可能口误**：保留教师原意摘要、冲突证据和疑点；除非教师明确自我修正，否则不静默裁决。
- **来源冲突**：并列写出各来源与定位，分析是否版本、条件或符号约定差异；无法证实时标 `unresolved`。
- **非专业性小错误**：页码、年份、人数、一般背景统计或排版笔误若不影响专业概念、公式、条件、推导、例题结果或考试结论，只在 Source Map 简短记为 `Minor source note`。不要提升为课程级疑点，不要求用户持续追查或修正。
- **缺失信息**：说明缺什么、影响哪一结论、需要什么材料才能解决。
- **不可读公式**：保留可确认部分，用 `[?]` 指明不确定位置，不按模式猜全。

不确定内容应集中、可行动。不要让 `[?]` 散落后无人知道如何核验。

冲突的处理权重由其教学影响决定，而不是由“是否存在差异”决定：

- 影响核心专业知识或计算结果：按 Blocker/Major 处理并进入人工复核。
- 影响局部解释但不改变核心结论：按 Major 或 Minor 处理。
- 仅属行政信息、背景统计或明显排版小误差：按 Minor 简记，不进入长期待办。

## 10. 全局资料编译规则

首次建库：

1. 盘点教材、syllabus、handout、formula sheet，建立 `Global_Source_Map.md`。
2. 只提取课程范围、主要单元、主题依赖、符号约定和重要资源位置。
3. 建立轻量 `Global_Knowledge.md`，不预先重写未讲到的教材章节。
4. 创建 `Course_Index.md`；未知 lecture 可只写课程单元，不编造日期和标题。

课程进行中：

- 新增 lecture 时，在 Course Index 增加一条入口、Topics 和状态。
- 只有出现新的跨课关系、课程约定或主线变化时才更新 Global Knowledge。
- 新发现更佳的全局定位、版本差异或冲突时更新 Global Source Map。
- 不因每节课的小细节频繁重写全局文件。

## 11. 更新与版本原则

- 编辑前保留原始资料；编译文档可直接迭代。
- 每次重大变更在 `Global_Knowledge.md` Change Log 或版本控制中说明原因。
- 同一讲次的 Notes 与 Source Map 状态应一致；若其中一份改变，检查另一份是否需同步。
- 新来源加入后，只重审受影响的知识项，不默认全库重编译。

## 12. 完成定义

一次单节课编译只有在以下条件同时满足时才算 `draft` 完成：

- 两个标准文件均已生成。
- 所有输入来源已列入 inventory，并标明是否成功读取。
- 常见来源类型的 availability 已记录；未提供的来源没有被误报为读取失败，也没有被假装覆盖。
- 关键定义、公式、推导、例题和教师强调已做来源映射。
- 所有冲突和不确定性已显式记录。
- QA 已执行，Blocker 为 0；未解决 Major 项已显式交给人审。
